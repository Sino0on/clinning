# Автодеплой бэкенда

**Обычный случай: ничего делать не нужно.** Пуш в `main`, и в течение минуты
сервер сам подхватит изменения. Обычные правки кода выкатываются без простоя.

## Как это устроено

На сервере `217.114.0.30` systemd-таймер `clinning-deploy.timer` раз в минуту
запускает [deploy.sh](deploy.sh) (на сервере: `/usr/local/bin/clinning-deploy`).
Скрипт сравнивает версию на сервере с `origin/main` и при расхождении:

1. делает бэкап базы в `/root/backups/clinning/auto/` (хранятся последние 20);
2. подтягивает код (`git merge --ff-only`);
3. если менялись `requirements.txt`, `Dockerfile` или `docker-compose*.yml`,
   пересобирает образ;
4. в отдельном контейнере на новом коде выполняет `manage.py check`, `migrate`
   и `collectstatic`;
5. плавно перезапускает gunicorn (HUP, без простоя). При пересборке образа
   контейнер пересоздаётся, и API несколько секунд недоступен;
6. проверяет, что `/api/items/` отвечает.

Если любой шаг не прошёл, код возвращается на предыдущий коммит, а неудачный
коммит больше не пробуется, пока в `main` не появится новый.

Схема «сервер сам забирает» выбрана потому, что для GitHub Actions нужны
секреты репозитория, а их может добавлять только владелец (`Sino0on`).

## Команды на сервере

```bash
ssh root@217.114.0.30
clinning-deploy status   # версия на сервере и в GitHub, последние деплои
clinning-deploy deploy   # задеплоить прямо сейчас (в том числе повторить неудачный)
```

Лог: `/var/log/clinning-deploy.log`. Выключить автодеплой:
`systemctl disable --now clinning-deploy.timer`.

## Откат

Сделайте `git revert` проблемного коммита и запушьте: откат задеплоится так же.
Миграции базы назад автоматически не откатываются. Для этого есть бэкапы в
`/root/backups/clinning/auto/`.

## Ежедневный бэкап

Таймер `clinning-backup.timer` каждую ночь (03:30 по Бишкеку) запускает
[backup.sh](backup.sh) (на сервере: `/usr/local/bin/clinning-backup`): база и
загруженные файлы, 14 дней, в `/root/backups/clinning/daily/ДАТА/`. Как
восстановить, написано в шапке скрипта. Бэкап лежит на том же сервере: от
ошибок спасает, от потери сервера — нет.

## Админка контента (приложение `content`)

Заказчица сама ведёт на сайте отзывы, «до/после», услуги, партнёров и бренды
химии в `/admin/`, тема — django-unfold 0.91 (последняя версия под Python 3.11).

- Фото при загрузке поворачиваются по EXIF и ужимаются (`content/media.py`).
- Видео-отзывы (до 300 МБ) сжимаются в фоне через ffmpeg, обложка делается
  сама (`content/video.py`). Застрявшие или упавшие видео: действие
  «Обработать видео заново» в списке отзывов или `manage.py process_videos`.
- Сайт берёт всё одним запросом `GET /api/content/`.
- После сохранения бэкенд сам обновляет сайт (`content/signals.py`): POST на
  `https://taza-ayim.kg/api/revalidate` с секретом `REVALIDATE_SECRET` из `.env`
  и прогрев страниц. Правка видна на сайте через ~10 секунд.
- Учётка для редактора без доступа к пользователям и настройкам:
  `python manage.py setup_content_editor --user ЛОГИН --first-name Имя`,
  затем пароль: `python manage.py changepassword ЛОГИН`.

## Страницы услуг (`/ru/uslugi/<адрес>`)

Отдельная посадочная страница под каждый вид уборки, для Google. Заказчица
создаёт их в админке «Страницы услуг»: проще всего кнопкой «Создать копию» у
готовой страницы. Копия скрыта с сайта, кыргызские тексты и тексты для Google
в ней пустые: если их не заполнить, на сайте возьмутся русские.

- Сайт берёт опубликованные страницы запросом `GET /api/content/pages/`. Новая
  страница открывается без пересборки сайта и сама попадает в sitemap.
- Пустые разделы (что входит, фото, вопросы) на странице не выводятся.
- У карточки услуги на главной, привязанной к странице («Публикация» →
  «Карточка на главной»), появляется кнопка «Подробнее».
- Права группе «Контент-менеджер» добавляет миграция `0004`.
- Страница-образец «Уборка после стройки» создаётся один раз командой
  `python manage.py create_example_service_page`. Если такая страница уже
  есть, команда ничего не меняет.

Выкатывать сначала бэкенд (миграции и API), потом сайт.

## Telegram-бот для отзывов

Сервис `bot` в `docker-compose.yml` (`manage.py run_telegram_bot`): заказчица
отправляет боту фото, скриншот или видео, нажимает «Опубликовать», и отзыв
появляется на сайте. Под опубликованным отзывом есть кнопка «Скрыть с сайта».
Видео сжимаются так же, как из админки, и бот пишет, когда видео готово.

- **Токен** от @BotFather задаётся на сервере: `ssh -t root@217.114.0.30
  clinning-set-bot-token` (ввод скрытый, токен проверяется у Telegram). Без
  токена бот просто спит.
- **Доступ** только по одноразовой ссылке-приглашению: в админке «Telegram-бот»
  → добавить приглашение (ссылка появится после сохранения) или
  `python manage.py telegram_invite --note "Для кого"`. Кто вошёл, видно в
  «Редакторы в Telegram», там же доступ можно закрыть.
- **Ограничение Telegram:** бот скачивает файлы до 20 МБ. Обычное видео Telegram
  сжимает при отправке; если файл больше, бот предложит админку.
- Автодеплой перезапускает бота вместе с бэкендом. Логи: `docker compose logs bot`.

## Если меняете файлы в этой папке

Сервер использует копии, их нужно обновить:

```bash
scp deploy/deploy.sh root@217.114.0.30:/usr/local/bin/clinning-deploy
scp deploy/backup.sh root@217.114.0.30:/usr/local/bin/clinning-backup
scp deploy/*.service deploy/*.timer root@217.114.0.30:/etc/systemd/system/
ssh root@217.114.0.30 'systemctl daemon-reload'
```
